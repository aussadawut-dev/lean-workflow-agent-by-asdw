# TCK010 — v5.2.0: `/lean-model-update` and `lean models eval`

Status: DONE
Owner: Controller (claude-opus-5-5)

## Goal

When models change, `/lean-model-update` produces a tested mapping for every size (3S-3XL) that can be repeated and compared across runs; `.lean/models.json` changes only after the user approves the diff.

## Acceptance criteria

- [x] AC-01: Skill `lean-model-update`: research → eval plan through scope (user approves candidates, tasks and a token cap) → `lean models eval` → independent review of results and proposal → proposed `models.json` diff → user approval → `lean models apply` and `models check --live`.
- [x] AC-02: `lean models eval --plan FILE --budget N`: subscription only (API keys removed), the `models.json` command shapes, a throwaway copy per run outside the repository (system temp folder), `--budget` required, each run reserves an estimate before it starts so the cap is exceeded only by a run that outgrows its reservation, unknown token counts charged like a reservation, subtest-level hidden-test scores, one token rule for every provider (input + cache writes + output; cache reads apart), resumable, results JSONL + summary + proposal under the chosen output folder, agy permission denials reported with the fix.
- [x] AC-03: `lean models apply --proposal FILE --sha256 DIGEST` writes only the proposed tiers, refuses a changed proposal, validates the list.
- [x] AC-04: Task bank `.lean/evals/<size>/` for all eight sizes, graded in difficulty; each reference solution scores full marks and each stub scores below full, its score recorded as the baseline (tested). Bug-fix and feature tasks start partly passing by nature.
- [x] AC-05: Tests with fake provider CLIs for budget stop, scoring, the three token formats, timeout, resume, missing budget, permission denial, proposal choice, apply digest; `lean test --all`, lint, gate PASS; independent HIGH review PASS of the uncommitted diff.
- [x] AC-06: MODELS.md, docs, CHANGELOG 5.2.0 (EN/TH); tag v5.2.0, GitHub Release, CI green.

## Decisions

- 2026-10-27 user: option A (skill + `lean models eval` + graded task bank) ("a"); task bank ships to every installation in `.lean/evals/`; one task per size for the first version ("1ตามแนะนำ 2ตามแนะนำ").
- Out of scope: scheduled or automatic eval runs; editing provider permission settings (the skill prints the command for the user); Codex `ultra`; running a real eval in this release.
- Review round 1 (2026-10-27): runs moved outside the repository (a Claude candidate inside it would load Lean's CLAUDE.md and could reach the task bank); budget reservations replace the start-only check; Claude gets an eval-only `--allowedTools` for the visible tests; a denied tool is a note, not a disqualification.
- Proposal rule: per provider and size, the fastest candidate with a full score on that size's task (times are comparable across providers, tokens are not).
