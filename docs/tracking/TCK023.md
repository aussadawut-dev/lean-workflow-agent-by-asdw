### Classification (re-checked at bca42e1)

(A) Confirmed defects — fix now

- 5 `lean update` false conflicts: confirmed. `update.py:258` compares `recorded["source"] == source` as strings, so an SSH pin updated over HTTPS gets no base and every upstream-changed file becomes `conflict`. Fix: compare a normalized repository identity (host + path, `.git` and `scp`/`ssh://`/`https://` forms unified); keep exact match for local paths.
- 6 impact map: confirmed. `.lean/upstream.json` is in `scope` (`.lean/*`) but in no rule or `lint_only`, so every pin move runs the full suite. All `assets.json` files are covered today; the gap is the project-owned files `lean update` writes. Fix: add the pin to `lint_only`, and make `lean lint` fail when a registry asset or project-owned workflow file in scope has no rule or lint-only entry.
- 7 stale version text: confirmed (partial in 5.6.0). The Purpose notice only matches `Lean Workflow Baseline X.Y.Z`; `Lean 5.3.1 uses tracker/direct` and a stale pinned commit pass silently. Fix: also match `Lean X.Y.Z` / `Lean vX.Y.Z` / `Lean Workflow X.Y.Z`, and note a Purpose that names the previously pinned commit. Automatic rewriting stays out (PROJECT.md is project-owned).
- 12 `Status:` line: confirmed as a diagnostics defect. A note after the state fails `mode check` with only `invalid tracker status: <path>`. Fix: name file:line and the offending text and point to the `Status note:` convention. The strict one-line format itself is kept (see B-12).
- 13 `gate mode <mode>` silent write: confirmed. `gate.write_mode` changes `.lean/gate.json` with no activity event and no hint. Fix: record a `gate-mode` event (session, before, after) and print that `.lean/gate.json` is project-owned and should be committed.
- 16b `lean contract current` requires `--session`: confirmed. Fix: default to the environment session the way `progress` does.
- 16c `lean evidence --help`: confirmed (`unrecognized arguments: --help`). Fix: pass it through to the evidence parser.

(B) Design decisions — proposals below; no rule changes without the user

- 1, 2, 3, 4, 8, 10, 11, 14, 15 as the user listed.
- 9 reclassified from (A): `guard.pre_tool` checks any tool that carries a `command` (Codex shell tools, MCP shells) and any tool writing the review receipt or gate caches. A matcher of `Edit|Write|MultiEdit|NotebookEdit|Bash` would drop those checks, so this is a trade-off, not a defect.
- 12 (accepting notes on the Status line) — format change, offered as an option.
- 16a manual-mode Stop text on stderr at exit 0 — whether to stay silent or show a short `systemMessage` every Stop is a user-visible choice.

### Design proposals (waiting for the user)

- B-1 Contract lifecycle. Options: (a) keep the contract for the session until redeclared or `lean contract clear`; a new prompt sets a "confirm same task" flag shown in status. (b) Make `lean contract declare` the only path and remove transcript binding (~150 lines + tests). (c) Keep transcript binding, raise `TRANSCRIPT_WAIT`, and replace the 8-line HELP on a race with a short retry hint. Downstream: (a) loosens a MEDIUM/HIGH rule (new prompt = new contract) and needs AGENTS.md/CONTRACTS.md wording and guard tests; (b) changes every agent's first move, needs migration notes; (c) no migration. Recommendation: (c) now, (a) as a MINOR with explicit opt-in.
- B-2 Shell write heuristic. Options: (a) treat `npm run|pnpm|yarn <script>` as reads except install/publish/add words, drop `build` from `INSTALL_WORDS`; (b) PROJECT.md allowlist of pre-contract commands; (c) extend the scratch exemption to Bash when every target path is under the scratch root. Downstream: (a) lets builds write before a contract (Stop gate still refuses undeclared changes); (b) new PROJECT.md section, lint support; (c) narrow and low risk. Recommendation: (c) + (b).
- B-3 Review receipts. Options: (a) keep many receipts keyed by (contract, state) in `.agent-runtime/receipts/`; (b) committable `docs/tracking/receipts/<state>.json`; (c) `refs/notes/lean-review`. Downstream: (b)/(c) make receipts forgeable by anyone with commit access, which weakens the "only the reviewer records" rule; needs a trust model and migration from `review.json`. Recommendation: (a) first (history, no travel); travel needs its own HIGH design.
- B-4 Dispatch records. Options: (a) `lean spawn run` parses the CLI's JSON output and writes the record; (b) policy accepts "runtime did not report" without the agent writing it. Downstream: (a) depends on provider output formats (needs per-provider tests and a fallback); (b) wording change in AGENTS.md, MODELS.md, lean-agents. Recommendation: (b) now, (a) later.
- B-8 Gate tiers. Options: (a) `gate:stop` and `gate:full` blocks in PROJECT.md, Stop runs only `gate:stop`; (b) keep one block, add per-check `stop`/`full` tags. Downstream: new PROJECT.md format, gate-result schema with two states, `lean status` and closure rules; DONE must still require `full`. Migration: one block stays valid as both tiers. Recommendation: (a) as a MINOR.
- B-9 Hook matcher. Options: (a) matcher limited to write tools + Bash (and Codex equivalents); (b) keep no matcher but return allow quickly before importing heavy modules; (c) keep as is. Downstream: (a) loses `command`-carrying unknown tools and receipt protection through other tools, and Codex tool names differ per version; (b) only speed. Recommendation: (b) or (c); (a) only with an explicit acceptance of the lost coverage.
- B-10 Runtime folder. Options: (a) move Lean state to `.agent-runtime/lean/` with update migration; (b) keep the folder, add pruning for stale markers and session files. Downstream: (a) touches every module that uses `RUNTIME`, guard path checks and docs; MAJOR-level path change for anything that reads these files. Recommendation: (b) now, (a) in a MAJOR.
- B-11 Footprint. Options: (a) `core` and `dev` asset groups, `lean update --with dev` opt-in; (b) keep shipping tests but make the consumer gate run only lint + smoke. Downstream: (a) changes registry schema and update; (b) changes the PROJECT.md gate template. Recommendation: (b) first, then (a).
- B-12 Status notes. Options: (a) accept `Status: STATE — note` / `(note)`; (b) keep strict (diagnostics fixed in A). Downstream: (a) every reader of the Status line and `tracker status` rewriting must keep the note. Recommendation: (b).
- B-14 Review depth per area. Options: (a) each High-risk area line carries `HIGH` or `MEDIUM` and the gate enforces the touched area's depth; (b) lean-init warns when globs cover too much. Downstream: CONTRACTS.md, REVIEW.md, gate floor logic, PROJECT.md format. Recommendation: (b) now, (a) as a MINOR.
- B-15 Tracker for short tasks. Options: (a) tracker required only for risk ≥ MEDIUM (configurable); (b) short template. Downstream: WORKFLOW.md and `mode check`. Recommendation: (a) behind a config flag.
- B-16a Manual-mode Stop text. Options: (a) drop the stderr text; (b) a one-line `systemMessage` "Quality Gate NOT_RUN (manual)". Recommendation: (b).
