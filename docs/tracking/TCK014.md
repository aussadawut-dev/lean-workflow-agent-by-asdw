# TCK014 — Change-scoped gate checks, batch gating and flaky reruns; release 5.3.0

Status: VALIDATING
Owner: claude

## Goal

Bring the gate rules proven in Casetodian TCK424 into Lean so every project gets them, then release TCK013 and these together as 5.3.0 for Casetodian TCK425 to apply with `lean update`:
1. A gate check can be skipped when the change touches only work records (trackers, queue items), failing safe toward running.
2. A multi-TCK batch runs one full gate; a suspected flaky failure gets at most 2 reruns.

## Decisions

- Generalised from Casetodian's `scripts/gate_scope.py`: default record globs cover workspace and `.lean/targets/*` trackers and queue items; project-specific paths (an application pointer, extra inputs) go through `--only`/`--always` instead of code. Change detection is `testsel.scope_paths()`: the diff from the merge-base with the remote default branch with `--ignore-submodules=none`, plus untracked files, so pushed but unmerged commits and submodule content count (stricter than `changed()`, after review round 1).
- MINOR release (5.3.0), not PATCH: TCK013 and TCK014 add commands and options.
