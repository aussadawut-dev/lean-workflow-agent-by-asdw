# TCK015 — Guard help, memory and gate-cache holes; per-session progress; release 5.3.1

Status: VALIDATING
Owner: claude

## Goal

Close three contract-guard holes found by Casetodian's post-5.3.0 audit and stop one session's progress bar from showing in another session's status line, then release 5.3.1 for Casetodian to apply with `lean update`.

## Acceptance criteria

- [x] AC-01: A `lean` command counts as usage text only when `-h`/`--help` comes before `--`; `lean gate scope` with a command is always a write. `lean gate scope -- rm -rf src -h` and `lean gate scope -- sh -c "echo x > f" --help` are writes; `lean -h`, `lean gate scope -h`, `lean evidence record-review --help` stay reads.
- [x] AC-02: The no-contract exception for files outside the repository covers only `/tmp`, `/private/tmp` and a flat user memory file `<base>/projects/<project>/memory/<file>`, where `<base>` is `~/.claude`, `$CLAUDE_CONFIG_DIR` or a `claude-profiles/<name>` (optionally `/home`) folder. Paths such as `<other checkout>/.claude/hooks/memory/x.sh` need a contract.
- [x] AC-03: Direct writes to `.agent-runtime/gate-cache` and `.agent-runtime/target-gate-cache` are refused like the review receipt; deleting them stays allowed.
- [x] AC-04: Progress is kept per session (`LEAN_SESSION_ID`, `CLAUDE_CODE_SESSION_ID` or `CODEX_THREAD_ID`); `lean status --line` reads the status-line session from stdin and shows that session's progress, and another session's progress only with a `session <id8>` label; hooks show the hook session's progress. Without a session id the old shared behaviour remains.
- [x] AC-05: Each fix has a regression test that fails before and passes after; version 5.3.1 with both changelogs; `lean lint`, tests and the gate pass; independent HIGH review PASS.
