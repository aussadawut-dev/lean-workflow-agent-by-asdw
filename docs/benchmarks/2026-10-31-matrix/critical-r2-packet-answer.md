The source supports tenant scoping and permission enforcement, but **does not establish complete concurrency safety**. No exploitable path is established here. Tests were inspected, not executed.

- **HTTP caller and workspace.** Controllers pass `scopedPrincipal.userId`, not the token subject or a body-supplied actor (`application/apps/api/src/modules/external-identities/external-identity.controller.ts:12`). The resolver maps verified subject/email to a workspace-local user; middleware rejects resolver/token workspace disagreement and installs the verified workspace scope (`application/packages/db/src/project-scope.ts:46`, `application/packages/mcp-runtime/src/auth.ts:69`). Identity HTTP tests inject authentication/resolution, so they do not independently establish production token verification (`application/apps/api/src/routes/external-identities.test.ts:22`).

- **Authorization and tenant boundaries.** All three operations resolve current database membership, active workspace, policy and entitlement inside their transaction, then require workspace-level `connectors.manage` (`application/packages/server/src/modules/external-identities/external-identity-admin.usecases.ts:18`, `application/packages/server/src/modules/access/access.repository.ts:8`). Queries constrain workspace; composite account keys and the workspace/identity foreign key reinforce isolation. ID-only reads/retirement updates rely on preceding scoped validation or newly created IDs (`application/packages/server/src/modules/external-identities/prisma-external-identity-admin.repository.ts:12`, `application/prisma/schema.prisma:1831`). Tests assert foreign-workspace rejection, unauthorized callers and policy denial (`application/packages/server/src/external-identities.test.ts:211`). Access is workspace-wide, without a project restriction.

- **Merge and retirement.** One transaction locks both identities in sorted order, rereads their scoped states, rejects missing/retired rows, moves accounts and retires the source. This provides explicit coordination for overlapping merges, without proving freedom from every deadlock involving other writers (`application/packages/server/src/modules/external-identities/external-identity-admin.usecases.ts:35`, `application/packages/server/src/modules/external-identities/prisma-external-identity-admin.repository.ts:10`). Allocation counts retired codes and both legacy/current prefixes as occupied; duplicate insertion retries (`application/packages/server/src/modules/external-identities/external-identity-codes.repository.ts:19`). Tests assert retirement, reservation and changed account lookups (`application/packages/server/src/external-identities.test.ts:161`). This is reservation by the shown allocator, not erasure.

- **Split uncertainty.** Split discovers an identity, locks it, rereads account ownership, checks the current identity has at least two accounts, then allocates and moves. **If ownership changed before lock acquisition, it does not lock the newly observed identity or restart** (`application/packages/server/src/modules/external-identities/external-identity-admin.usecases.ts:52`). That leaves serialization of the count/move decision unestablished. Concurrent tests exercise code allocation; administration tests exercise sequential merge/split behavior (`application/packages/server/src/external-identities.test.ts:81`, `application/packages/server/src/external-identities.test.ts:192`).

- **Revocation uncertainty.** HTTP middleware checks workspace writability and permissions, then conditionally rechecks authorization after the handler succeeds. That final check follows transaction completion; it cannot roll back a committed mutation. Identity authorization does not lock workspace/policy rows or recheck after identity-lock waits (`application/apps/api/src/app.ts:270`, `application/packages/server/src/modules/external-identities/external-identity-admin.usecases.ts:40`). Immediate revocation serialization is therefore unproven.

- **Privacy.** Authorized listing deliberately exposes real names, account IDs and timestamps. Other inspected readers resolve current pseudonyms while retaining provider IDs; merging increases cross-system linkability, and splitting changes current labels rather than deleting identity data (`application/packages/server/src/modules/external-identities/external-identity-admin.usecases.ts:11`, `application/packages/server/src/shared/external-owner-identities.ts:17`). Privacy tests assert sampled output scrubbing and merge-following reads, not universal anonymization; one calls `listExternalIdentities()` without its required user ID (`application/packages/server/src/external-identity-privacy.test.ts:88`).

Bounded regressions should cover ownership changing before split’s lock, simultaneous same/different-account splits and overlapping merges, and revocation during a lock wait—asserting both HTTP outcome and persisted state. Add post-split privacy reads and correct the stale privacy-test invocation. Runtime isolation settings, actual interleavings and deployed behavior remain unverified.
