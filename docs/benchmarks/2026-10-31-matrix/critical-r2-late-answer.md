Source shows explicit tenant and permission controls, plus transactional mutations. It does **not establish complete concurrency safety**. I found no demonstrated exploitable cross-tenant path. Tests were inspected, not executed.

- **Caller and authorization:** HTTP handlers pass `scopedPrincipal.userId`, never a body-supplied caller ID (`application/apps/api/src/modules/external-identities/external-identity.controller.ts:11`). Shared authentication verifies the bearer, rejects resolver/workspace mismatches, and establishes workspace context (`application/packages/mcp-runtime/src/auth.ts:69`). Every identity route requires `connectors.manage`, including GET (`application/packages/contracts/src/access-routes.ts:44`). Each use case independently reloads the caller within its transaction, requiring membership in an active workspace and current policy/entitlement-derived permission (`application/packages/server/src/modules/access/access.repository.ts:8`, `application/packages/server/src/modules/external-identities/external-identity-admin.usecases.ts:18`). These are workspace-wide operations; project membership does not narrow the identity list.

- **Tenant boundaries:** List filters by workspace, active status and nonempty accounts, returning at most 1,000 identities with `truncated`. Merge scopes locks/state lookup/account movement; split scopes account lookup/count/update. Final reads and retirement updates use identity ID alone, relying on earlier scoped validation or creation. The composite account-to-identity foreign key additionally prevents cross-workspace attachment (`application/packages/server/src/modules/external-identities/prisma-external-identity-admin.repository.ts:12`, `application/prisma/schema.prisma:1831`). Sequential cross-workspace denials and an attempted cross-workspace FK update have assertions (`application/packages/server/src/external-identities.test.ts:129`, `application/packages/server/src/external-identities.test.ts:211`).

- **Merge concurrency:** One transaction locks distinct identity IDs in sorted order with `FOR UPDATE`, then rereads existence/retirement before moving accounts and retiring the source (`application/packages/server/src/modules/external-identities/prisma-external-identity-admin.repository.ts:18`, `application/packages/server/src/modules/external-identities/external-identity-admin.usecases.ts:40`). This coordinates overlapping merges and reduces lock-order deadlocks. No isolation override or retry is specified; runtime isolation and concurrent outcomes remain unverified.

- **Split concurrency gap:** Split finds identity A, locks A, then rereads the account’s **current** identity. If a merge moved that account A→B before the lock, split counts B’s accounts and moves the account without locking B or checking `current === found`. Thus the recheck does not establish serialization with operations locking B (`application/packages/server/src/modules/external-identities/external-identity-admin.usecases.ts:55`). Authorization also precedes lock waits. HTTP’s conditional post-handler permission recheck can reject the response after mutation commits; it cannot undo that commit (`application/apps/api/src/app.ts:299`). These are concurrency limitations, not demonstrated authorization exploits.

- **Retirement:** Merge preserves the target code and retains the retired source row. Allocation includes retired codes and both legacy/current prefixes; uniqueness plus duplicate-skipping insertion handles competing allocations (`application/packages/server/src/modules/external-identities/external-identity-codes.repository.ts:19`). Tests assert retirement, rejection of retired endpoints, non-reuse and fresh-code splitting (`application/packages/server/src/external-identities.test.ts:161`). Concurrent tests exercise allocation, not merge/split (`application/packages/server/src/external-identities.test.ts:81`).

- **Privacy:** Managers intentionally receive real names, account IDs, timestamps and cross-system associations. Ordinary comment/owner reads resolve current pseudonyms, so merges retrospectively link those views; external account IDs remain exposed (`application/packages/server/src/modules/external-content/external-content.adapter.ts:183`, `application/packages/server/src/shared/external-owner-identities.ts:16`). Split changes mappings, not historical disclosures or copies: this is pseudonymization, not anonymization. HTTP tests assert manager access and foreign-name exclusion using injected authentication (`application/apps/api/src/routes/external-identities.test.ts:22`). Privacy tests assert name exclusion and merge-following reads, but one calls `listExternalIdentities()` without its required caller ID, limiting confidence in that test’s current viability (`application/packages/server/src/external-identity-privacy.test.ts:112`).

Bounded regressions should cover barrier-controlled stale-A/current-B splitting alongside another split/merge; opposing merges; resolver reads during retirement; permission revocation while waiting; and ordinary comment/owner reads after split. Assert final mappings, retirement, account conservation and response/commit consistency. No deployed-safety conclusion follows from this inspection.
