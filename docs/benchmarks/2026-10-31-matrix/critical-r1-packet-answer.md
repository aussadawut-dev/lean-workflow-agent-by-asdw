Source supports tenant and permission barriers, transactional merges, and code reservation. It does **not establish complete concurrency safety or anonymity**. This was source inspection only; no tests were executed.

- **HTTP caller and authorization.** Handlers pass `scopedPrincipal.userId`, never a body-supplied actor ID (`application/apps/api/src/modules/external-identities/external-identity.controller.ts:12`). Middleware verifies the bearer token, rejects a resolved workspace mismatch, and establishes workspace scope (`application/packages/mcp-runtime/src/auth.ts:69`). The production resolver matches verified subject/email within that workspace and returns the local user ID and role (`application/packages/db/src/project-scope.ts:46`). Every identity route requires `connectors.manage`, including GET; each use case additionally reloads authorization inside its transaction, requiring an active workspace member and current policy permission (`application/packages/contracts/src/access-routes.ts:44`, `application/packages/server/src/modules/external-identities/external-identity-admin.usecases.ts:18`, `application/packages/server/src/modules/access/access.repository.ts:8`). This is workspace-wide authority, without project filtering.

- **Tenant isolation.** List, lock, state checks, account lookup/count/movement all constrain workspace. Final reads and source retirement use ID alone, but their IDs originate from scoped validation or creation (`application/packages/server/src/modules/external-identities/prisma-external-identity-admin.repository.ts:12`). The composite account-to-identity foreign key independently prevents cross-workspace attachment (`application/prisma/schema.prisma:1848`). Tests assert foreign-workspace rejection, permission denial, policy override enforcement, and database rejection of cross-workspace linkage (`application/packages/server/src/external-identities.test.ts:129`, `application/packages/server/src/external-identities.test.ts:211`). HTTP tests inject authentication/resolution, so they do not establish production JWT verification (`application/apps/api/src/routes/external-identities.test.ts:22`).

- **Transactions and concurrency.** Merge locks both identity rows in sorted order, then checks existence/retirement before moving accounts and retiring the source (`application/packages/server/src/modules/external-identities/external-identity-admin.usecases.ts:40`, `application/packages/server/src/modules/external-identities/prisma-external-identity-admin.repository.ts:18`). Split rereads ownership after locking, but if ownership changed, it neither locks the newly observed identity nor retries; movement is unconditional on the previously observed identity (`application/packages/server/src/modules/external-identities/external-identity-admin.usecases.ts:55`, `application/packages/server/src/modules/external-identities/prisma-external-identity-admin.repository.ts:39`). Thus split serialization is unproven when a merge moves the account between lookup and lock. Transaction isolation is not explicitly configured here (`application/packages/server/src/modules/external-identities/prisma-external-identity-admin.repository.ts:10`). Authorization precedes identity-lock waits without locking policy/workspace state; HTTP’s later permission check occurs after the mutation transaction, so rejection then cannot establish rollback (`application/apps/api/src/app.ts:303`).

- **Retirement.** Allocation considers active and retired codes across both prefixes; uniqueness collisions use `skipDuplicates` with bounded retries (`application/packages/server/src/modules/external-identities/external-identity-codes.repository.ts:19`). Sequential tests assert retirement, rejection of retired identities, non-reuse, and fresh split codes (`application/packages/server/src/external-identities.test.ts:161`). Concurrent tests exercise account/code allocation, **not merge/split interleavings** (`application/packages/server/src/external-identities.test.ts:81`).

- **Privacy.** Manager responses deliberately disclose real names, account IDs, timestamps and identity groupings; list excludes retired/empty identities and caps results at 1,000 (`application/packages/server/src/modules/external-identities/external-identity-admin.usecases.ts:9`, `application/packages/server/src/modules/external-identities/prisma-external-identity-admin.repository.ts:7`). Ordinary comments/owners retain provider IDs while resolving current pseudonyms, so merge links previously separate accounts and changes later attribution; split separates current mappings without erasing historical observations (`application/packages/server/src/shared/external-owner-identities.ts:17`, `application/packages/server/src/modules/external-content/external-content.adapter.ts:184`). Privacy tests assert name suppression and post-merge attribution, not anonymity or all-channel erasure (`application/packages/server/src/external-identity-privacy.test.ts:88`, `application/packages/server/src/external-identity-privacy.test.ts:130`). One calls `listExternalIdentities()` without its required actor argument, limiting confidence in that test’s current validity.

Bounded regressions: deterministically pause split across merge and race another split; test reciprocal/overlapping merges; revoke permission while an identity lock is awaited and inspect committed state independently of HTTP status; verify post-split comment/owner attribution. These target unsupported guarantees, not demonstrated exploits.
