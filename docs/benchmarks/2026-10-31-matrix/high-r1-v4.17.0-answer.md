The inspected SMTP path validates all resolved addresses and connects using the selected IP while retaining the original hostname for TLS identity. This is source evidence, **not proof of complete SSRF safety**. No tests, network calls, or product edits were performed.

All paths below are under `application/packages/server/src/`.

- **Ports:** Only integer ports **25, 465, 587, 2525** pass normally. `allowAnyPort: true` bypasses this policy check entirely. Sending rechecks the port before resolution or connection. Tests cover allowed ports, rejected ports/nonintegers, the override, and send-time rejection. `application/packages/server/src/infrastructure/providers/smtp-outbound-policy.ts#L3`, `application/packages/server/src/infrastructure/providers/smtp-client.ts#L198`, `application/packages/server/src/smtp-outbound-policy.test.ts#L11`, `application/packages/server/src/smtp-connector.test.ts#L901`.

- **Address classification:** IPv4 always-denied ranges are `0/8`, `169.254/16`, `192.0.0/24`, multicast `224/4`, reserved `240/4`, plus `100.100.100.200` and `168.63.129.16`. Loopback is `127/8`; private includes RFC1918 and CGNAT `100.64/10`. IPv6 denies unspecified, link-local, multicast, NAT64 `64:ff9b::/96`, 6to4 `2002::/16`, Teredo `2001::/32`, and `fd00:ec2::254`; `::1` is loopback and `fc00::/7` private. Zone identifiers and invalid addresses are denied. Other valid addresses fall through to `"public"`—that label is not an exhaustive global-routability determination. `application/packages/server/src/infrastructure/providers/smtp-outbound-policy.ts#L34`, `application/packages/server/src/infrastructure/providers/smtp-outbound-policy.ts#L84`.

- **IPv4 inside IPv6:** Dotted tails and compressed/hextet representations are parsed. IPv4-mapped and IPv4-compatible forms recursively inherit the embedded IPv4 classification; native `::` and `::1` retain their special handling. Tests cover mapped loopback, metadata, private, and public examples in dotted/hextet forms. `application/packages/server/src/infrastructure/providers/smtp-outbound-policy.ts#L61`, `application/packages/server/src/smtp-outbound-policy.test.ts#L27`.

- **DNS:** Literals bypass resolution. Hostnames use `lookup({ all: true, verbatim: true })`; every returned address must satisfy policy. One prohibited address rejects the entire mixed response. Resolver exceptions and empty answers become `SMTP_TARGET_REFUSED`; only after validation is the first address selected. Tests explicitly cover these cases and one resolver invocation. `application/packages/server/src/infrastructure/providers/smtp-outbound-policy.ts#L117`, `application/packages/server/src/smtp-outbound-policy.test.ts#L81`.

- **Relaxations:** `SMTP_ALLOW_PRIVATE_HOSTS` must equal lowercase `"true"`; explicit `allowPrivate` overrides it. Neither permits loopback or always-denied addresses. `allowLoopback` independently permits loopback. These are caller-supplied options without a runtime test-environment restriction; tests use them as seams. `application/packages/server/src/infrastructure/providers/smtp-outbound-policy.ts#L139`, `application/packages/server/src/smtp-outbound-policy.test.ts#L114`, `application/packages/server/src/smtp-connector.test.ts#L327`.

- **Connection and TLS identity:** Plain TCP and implicit TLS receive `target.address`, not the DNS hostname. STARTTLS wraps the existing vetted socket. TLS receives the original DNS hostname as `servername` and sets `rejectUnauthorized: true`; IP literals omit SNI and supply the IP identity for verification. Tests specify hostname SNI, untrusted/wrong-name certificate rejection, IP-SAN success, and checked-IP/single-resolution behavior. `application/packages/server/src/infrastructure/providers/smtp-client.ts#L92`, `application/packages/server/src/infrastructure/providers/smtp-client.ts#L218`, `application/packages/server/src/smtp-connector.test.ts#L673`.

**Remaining evidence gaps:** The inspected tests lack explicit IPv4-compatible, Teredo, IPv6 connection, wrong-IP-SAN, and STARTTLS hostname-mismatch cases. The environment/loopback integration test uses an ephemeral disallowed port, so port rejection can mask address-policy behavior (`application/packages/server/src/smtp-connector.test.ts#L915`). Default resolver behavior, runtime TLS semantics, deployment settings, routing/translation, and omitted special-purpose ranges remain unverified. The separate email-API transport also bypasses this SMTP path and was not audited (`application/packages/server/src/infrastructure/providers/smtp-client.ts#L185`).
