Source supports tenant isolation and permission checks for these paths. It does **not establish complete concurrency safety or anonymization**. This was read-only inspection; no tests were executed.

- **HTTP caller and authorization.** Controllers pass `scopedPrincipal.userId`, never a body-supplied actor (`application/apps/api/src/modules/external-identities/external-identity.controller.ts:11`). Bearer authentication resolves a local principal, rejects workspace mismatch and establishes async workspace scope (`application/packages/mcp-runtime/src/auth.ts:69`). The default resolver requires verified email and matches subject/email within that workspace (`application/packages/db/src/project-scope.ts:67`). All three use cases resolve access inside their transaction and require workspace-wide `connectors.manage`; this grants access across projects (`application/packages/server/src/modules/external-identities/external-identity-admin.usecases.ts:18`). Resolution checks active membership, policy and entitlement (`application/packages/server/src/modules/access/access.repository.ts:8`).

- **Tenant boundary.** List, locks, state checks and account operations filter workspace. ID-only final reads/retirement updates rely on preceding scoped validation or locally created IDs (`application/packages/server/src/modules/external-identities/prisma-external-identity-admin.repository.ts:12`). A composite foreign key prevents cross-workspace account attachment (`application/prisma/schema.prisma:1857`). HTTP tests assert unauthenticated/unauthorized rejection and foreign-workspace exclusion, using injected authentication dependencies (`application/apps/api/src/routes/external-identities.test.ts:22`); repository tests assert foreign attachment rejection (`application/packages/server/src/external-identities.test.ts:129`).

- **Transactions and concurrency.** Merge locks both identities in sorted order, then rereads existence/retirement before moving accounts and retiring the source atomically (`application/packages/server/src/modules/external-identities/prisma-external-identity-admin.repository.ts:18`, `application/packages/server/src/modules/external-identities/external-identity-admin.usecases.ts:40`). Split locks the initially found identity but rereads and uses a potentially different identity without locking it (`application/packages/server/src/modules/external-identities/external-identity-admin.usecases.ts:55`). Concrete concern: split reads account→A; merge A→B commits; split locks A and counts B while another split locks B. Under statement-level snapshots, both could observe two accounts before moving different accounts. Isolation is unspecified in the transaction wrapper; this is an unverified invariant risk, not an established exploit. Existing concurrency assertions concern allocation, while administration tests are sequential (`application/packages/server/src/external-identities.test.ts:81`).

- **Authorization races.** Authorization precedes identity-lock waits, without permission revalidation inside the mutation transaction. HTTP middleware conditionally rechecks after the handler, which can reject a response after mutation commits; it cannot roll back that commit (`application/apps/api/src/app.ts:299`). Concurrent revocation semantics remain unproven.

- **Retirement.** These paths retain retired rows; allocation reserves active/retired suffixes across current and legacy prefixes and retries duplicate insertions (`application/packages/server/src/modules/external-identities/external-identity-codes.repository.ts:19`). Tests assert target-code retention, source reservation and fresh split codes (`application/packages/server/src/external-identities.test.ts:161`).

- **Privacy.** Managers receive real names, account IDs and timestamps. Ordinary readers resolve current pseudonyms, so merges link accounts and splits change subsequent names; provider IDs remain visible (`application/packages/server/src/shared/external-owner-identities.ts:11`, `application/packages/server/src/modules/external-content/external-content.adapter.ts:184`). Comment bodies reach summary prompts without personal-data redaction (`application/packages/server/src/modules/external-content/external-content-summary.adapter.ts:64`). Privacy tests contain name-exclusion and post-merge assertions, but also a stale caller-less list invocation (`application/packages/server/src/external-identity-privacy.test.ts:112`); migration assertions explicitly retain a malformed non-array object’s name (`application/packages/server/src/external-identity-privacy.test.ts:220`).

Bounded regressions: barrier-controlled merge/split/split and opposing merges; revocation during lock waits with response/database assertions; post-split comment/owner reads; repair the stale privacy fixture and test documented handling of body-embedded names/malformed owners. Deployment configuration, actual isolation and deployed safety remain unverified.
