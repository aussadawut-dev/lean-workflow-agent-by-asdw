The inspected paths support workspace isolation and permission-gated administration. They do **not** establish complete concurrency safety or comprehensive privacy protection. No concrete cross-tenant exploit was established.

- **Caller identity and authorization.** HTTP handlers take `userId` from `scopedPrincipal`, not request bodies (`application/apps/api/src/modules/external-identities/external-identity.controller.ts#L12`). Bearer middleware verifies the token, rejects resolver/workspace disagreement, and binds workspace context (`application/packages/mcp-runtime/src/auth.ts#L69`). Production account resolution checks verified email and subject within that workspace (`application/packages/db/src/project-scope.ts#L67`). HTTP middleware applies the role/permission gate; each use case independently resolves current database permissions inside its transaction, requiring `connectors.manage` (`application/apps/api/src/app.ts#L299`, `application/packages/server/src/modules/external-identities/external-identity-admin.usecases.ts#L18`). This is workspace administration, without a project-specific restriction.

- **Tenant boundaries.** List filters workspace, retired status and nonempty accounts, returning at most 1,000 identities with a truncation flag. Merge checks both identities within the workspace; split locates accounts by `(workspaceId, kind, accountId)` (`application/packages/server/src/modules/external-identities/prisma-external-identity-admin.repository.ts#L12`). Final identity reads and retirement updates use globally unique IDs without another workspace predicate, but their callers first validate those IDs or create them locally. The composite foreign key prevents cross-workspace account attachment (`application/prisma/schema.prisma#L1856`). HTTP tests assert foreign-data exclusion, unauthorized-role denial and foreign-ID rejection, using injected authentication rather than real token verification (`application/apps/api/src/routes/external-identities.test.ts#L22`); server tests additionally cover mixed-workspace merges and the foreign-key constraint (`application/packages/server/src/external-identities.test.ts#L129`, `application/packages/server/src/external-identities.test.ts#L211`).

- **Concurrency limitations.** Merge orders identity row locks, then rechecks existence/retirement before moving accounts and retiring the source atomically. Split rereads account ownership after locking its initially observed identity (`application/packages/server/src/modules/external-identities/external-identity-admin.usecases.ts#L40`). However, if a merge moves that account from A to B before split acquires A’s lock, split proceeds using B without explicitly locking B or restarting. Its update also lacks an expected-old-identity predicate (`application/packages/server/src/modules/external-identities/prisma-external-identity-admin.repository.ts#L39`). Serialization against operations on B therefore remains unestablished; actual outcomes depend on database isolation and scheduling. The transaction wrapper specifies no isolation override (`application/packages/server/src/modules/external-identities/prisma-external-identity-admin.repository.ts#L10`). Authorization is checked before identity-lock waits; the conditional HTTP permission recheck occurs after the handler transaction returns and cannot itself roll back committed changes (`application/apps/api/src/app.ts#L304`). Existing concurrent tests exercise allocation, not these administration interleavings (`application/packages/server/src/external-identities.test.ts#L81`).

- **Code retirement.** Merge retains the source row/code as retired; allocation treats active and retired suffixes under both prefixes as occupied and retries conflicting inserts (`application/packages/server/src/modules/external-identities/external-identity-codes.repository.ts#L19`, `application/packages/server/src/modules/external-identities/external-identity-codes.repository.ts#L62`). Tests assert reservation, subsequent resolution to the target, and fresh-code splitting (`application/packages/server/src/external-identities.test.ts#L161`). These are source assertions, not guarantees against arbitrary deletion or external writers.

- **Privacy impact.** Admin responses intentionally expose account IDs, real display names, timestamps and cross-system linkage. Other inspected readers substitute current pseudonyms while retaining external account IDs (`application/packages/server/src/modules/external-content/external-content.adapter.ts#L183`). This is pseudonymization, not anonymity: merge links identities; split does not erase prior disclosures. Tests cover selected comments, owners, AI inputs, notifications and stored fields, plus later reads following merges (`application/packages/server/src/external-identity-privacy.test.ts#L88`, `application/packages/server/src/external-identity-privacy.test.ts#L130`). However, its admin-list assertion omits the required caller ID (`application/packages/server/src/external-identity-privacy.test.ts#L112`), limiting confidence in that test as written.
