The source implements address vetting and connection pinning, but does **not establish complete SSRF safety**. This was an offline source review; no tests or network operations were run.

- **Ports:** Only integer ports **25, 465, 587, 2525** pass normally. `allowAnyPort: true` bypasses that check entirely. Settings updates also enforce the allowlist, and sending checks again before DNS/socket creation. See `application/packages/server/src/infrastructure/providers/smtp-outbound-policy.ts:3`, `application/packages/server/src/modules/connectors/connector-settings.usecases.ts:284`, `application/packages/server/src/infrastructure/providers/smtp-client.ts:198`. - **Address classification:** IPv4 always-denied ranges are `0/8`, `169.254/16`, `192.0.0/24`, `224/4`, `240/4`, plus `100.100.100.200` and `168.63.129.16`. Loopback is `127/8`; private includes RFC1918 and `100.64/10`. IPv6 denies unspecified, link-local, multicast, `64:ff9b::/96`, `2002::/16`, `2001::/32`, and `fd00:ec2::254`; `::1` is loopback and `fc00::/7` private. Zone identifiers and invalid addresses are denied. Otherwise the classification falls through to `"public"`—not necessarily globally routable. `application/packages/server/src/infrastructure/providers/smtp-outbound-policy.ts:34`, `application/packages/server/src/infrastructure/providers/smtp-outbound-policy.ts:84`.

- **IPv4 inside IPv6:** Dotted tails are converted to hextets. IPv4-mapped and IPv4-compatible forms recursively receive IPv4 classification, preserving native `::`/`::1` handling. The transition prefixes above are blocked wholesale. Tests cover mapped dotted/hex loopback, metadata, private/public addresses, NAT64 and 6to4 examples; I found no IPv4-compatible-form or Teredo assertion in this suite. `application/packages/server/src/infrastructure/providers/smtp-outbound-policy.ts:61`, `application/packages/server/src/smtp-outbound-policy.test.ts:27`.

- **DNS:** Literals bypass resolution; names use `lookup(..., {all:true, verbatim:true})`. Every returned address must pass: a public answer cannot compensate for a forbidden answer. Tests explicitly cover these behaviors. `application/packages/server/src/infrastructure/providers/smtp-outbound-policy.ts:117`, `application/packages/server/src/smtp-outbound-policy.test.ts:81`.
