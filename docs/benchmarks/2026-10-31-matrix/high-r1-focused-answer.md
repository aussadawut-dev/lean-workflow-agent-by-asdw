The inspected SMTP path validates destinations before connecting and uses the selected IP while retaining TLS hostname identity. This is source evidence for specific defenses, **not complete SSRF safety**. Tests were inspected, not executed; no traffic was sent.

All paths below are under `application/`.

- **Ports:** Only integer ports **25, 465, 587, 2525** pass normally. `allowAnyPort: true` bypasses this check entirely. Settings save enforces the allowlist, and sending checks again before DNS/socket creation. Evidence: `application/packages/server/src/infrastructure/providers/smtp-outbound-policy.ts#L3`, `application/packages/server/src/modules/connectors/connector-settings.usecases.ts#L284`, `application/packages/server/src/infrastructure/providers/smtp-client.ts#L198`. Tests cover allowed/disallowed values, the bypass, and send-time rechecking: `application/packages/server/src/smtp-outbound-policy.test.ts#L11`, `application/packages/server/src/smtp-connector.test.ts#L901`.

- **Address classification:** IPv4 denies `0/8`, link-local, `192.0.0/24`, multicast, `240/4`, and explicit metadata/service addresses `100.100.100.200` and `168.63.129.16`. Loopback is `127/8`; private includes RFC1918 and `100.64/10`. IPv6 denies unspecified, link-local, multicast, `64:ff9b::/96`, `2002::/16`, `2001::/32`, and `fd00:ec2::254`; `::1` is loopback and `fc00::/7` private. Invalid addresses and zone identifiers are denied. Everything else falls into “public.” `application/packages/server/src/infrastructure/providers/smtp-outbound-policy.ts#L34`; `application/packages/server/src/smtp-outbound-policy.test.ts#L27`.

- **IPv4 inside IPv6:** The parser normalizes dotted/hextet forms. IPv4-mapped (`::ffff:…`) and compatible (`::…`, excluding unspecified/loopback) forms recursively receive IPv4 classification, preventing mapped metadata/private/loopback bypasses. Listed transition prefixes are denied wholesale. `application/packages/server/src/infrastructure/providers/smtp-outbound-policy.ts#L61`. Tests cover mapped dotted/hextet forms and selected transition addresses, but I found no explicit compatible-address or `2001::/32` case. `application/packages/server/src/smtp-outbound-policy.test.ts#L28`.

- **DNS:** Literals bypass resolution. Hostnames use one `lookup({all:true, verbatim:true})`; **every returned address must pass**, then the first is selected. Thus a mixed public/rejected answer rejects entirely under the active options. Resolution exceptions and empty results become `SMTP_TARGET_REFUSED`. `application/packages/server/src/infrastructure/providers/smtp-outbound-policy.ts#L117`; `application/packages/server/src/smtp-outbound-policy.test.ts#L81`, `application/packages/server/src/smtp-connector.test.ts#L877`.

- **Relaxations:** Exact `SMTP_ALLOW_PRIVATE_HOSTS="true"` permits private addresses; explicit `allowPrivate` overrides it. Loopback separately requires `allowLoopback: true`; denied addresses remain denied. These options are **not guarded by `NODE_ENV`**. Tests inject loopback, arbitrary ports, resolver, and CA. The inspected admin HTTP endpoint forwards only role/recipient, leaving internal options at defaults. `application/packages/server/src/infrastructure/providers/smtp-outbound-policy.ts#L139`, `application/packages/server/src/smtp-outbound-policy.test.ts#L105`, `application/packages/server/src/smtp-connector.test.ts#L327`, `application/apps/api/src/modules/connectors/connector-settings.controller.ts#L227`, `application/apps/api/src/routes/connector-settings.test.ts#L336`.

- **Connection and TLS:** TCP and implicit TLS receive `target.address`; STARTTLS wraps that existing socket. DNS hostnames supply original `servername`, with `rejectUnauthorized: true`; IP literals omit SNI and retain IP identity. `application/packages/server/src/infrastructure/providers/smtp-client.ts#L92`, `application/packages/server/src/infrastructure/providers/smtp-client.ts#L218`. Tests assert checked-IP/single-resolution behavior, SNI, trusted/untrusted certificates, wrong-host rejection, and IP-SAN success. `application/packages/server/src/smtp-connector.test.ts#L673`.

Remaining gaps: “public” is a residual classification, not verified global routability; unlisted special/translation ranges need assessment. Inspected tests do not establish default-resolver behavior, changing-DNS scenarios, native IPv6 connections, or negative IP-SAN matching. Some refusal tests observe an unrelated ephemeral listener while configuring port 587, so zero connections there alone proves little; the no-seam loopback test may reject its ephemeral port first. `application/packages/server/src/smtp-connector.test.ts#L858`. Runtime, routing, and deployed configuration remain unverified.
