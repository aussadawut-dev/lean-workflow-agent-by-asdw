The inspected SMTP path has explicit destination filtering and connects to the selected, vetted IP while retaining TLS hostname identity. This is source evidence, not proof of complete SSRF safety. No tests or network operations were executed.

- **Ports:** Only integer ports **25, 465, 587, 2525** are allowed by default. Configuration saves check this allowlist, and sending rechecks it before DNS or socket creation. `allowAnyPort: true` bypasses the policy check entirely. Evidence: `application/packages/server/src/infrastructure/providers/smtp-outbound-policy.ts:3`, `application/packages/server/src/modules/connectors/connector-settings.usecases.ts:284`, `application/packages/server/src/infrastructure/providers/smtp-client.ts:198`. Tests specify allowed/disallowed ports and the bypass: `application/packages/server/src/smtp-outbound-policy.test.ts:11`.

- **Address classification:** IPv4 denial covers `0/8`, link-local, `192.0.0/24`, multicast, `240/4`, and two explicit cloud-service addresses. Loopback is separate; RFC1918 and `100.64/10` are private. IPv6 denial covers unspecified, link-local, multicast, `64:ff9b::/96`, `2002::/16`, `2001::/32`, and explicit metadata `fd00:ec2::254`; `::1` is loopback and `fc00::/7` private. Zone identifiers and invalid IP strings are denied. Unmatched valid addresses become “public.” `application/packages/server/src/infrastructure/providers/smtp-outbound-policy.ts:34`, `application/packages/server/src/infrastructure/providers/smtp-outbound-policy.ts:84`; representative tests: `application/packages/server/src/smtp-outbound-policy.test.ts:27`.

- **IPv4 embedded in IPv6:** Dotted tails and hexadecimal hextets are normalized. IPv4-mapped and IPv4-compatible forms recursively receive IPv4 classification; compatible-form extraction excludes `::` and `::1`, preserving their special handling. Thus embedding does not automatically make private/metadata IPv4 public. `application/packages/server/src/infrastructure/providers/smtp-outbound-policy.ts:61`. Tests cover mapped loopback, private, metadata and public addresses, but I found no IPv4-compatible-form cases in that suite. `application/packages/server/src/smtp-outbound-policy.test.ts:27`.

- **DNS:** Literals skip lookup; names use one `lookup(..., { all: true, verbatim: true })`. Every returned address must be permitted before the first is selected. A public answer alongside a disallowed answer therefore fails. Lookup exceptions and empty answers both become `SMTP_TARGET_REFUSED`. `application/packages/server/src/infrastructure/providers/smtp-outbound-policy.ts:117`; injected-resolver tests: `application/packages/server/src/smtp-outbound-policy.test.ts:82`.

- **Relaxations:** Exact environment value `SMTP_ALLOW_PRIVATE_HOSTS="true"` permits private addresses. Explicit `allowPrivate` overrides it. `allowLoopback: true` separately permits loopback; neither overrides “denied.” Tests exercise these distinctions. These are callable options, with **no test-environment guard**. `application/packages/server/src/infrastructure/providers/smtp-outbound-policy.ts:139`, `application/packages/server/src/smtp-outbound-policy.test.ts:105`. The inspected HTTP endpoint supplies no internal-options argument: `application/apps/api/src/modules/connectors/connector-settings.controller.ts:227`.

- **Connection and TLS:** Plain TCP and implicit TLS use `target.address`. STARTTLS wraps that existing TCP socket. Hostnames remain `servername`; certificate verification stays enabled. IP literals omit SNI, with their IP retained for identity checking. `application/packages/server/src/infrastructure/providers/smtp-client.ts:92`, `application/packages/server/src/infrastructure/providers/smtp-client.ts:218`. Tests specify SNI, untrusted-certificate and hostname-mismatch rejection, IP-SAN success, and checked-IP connection: `application/packages/server/src/smtp-connector.test.ts:673`.

Remaining gaps: finite deny lists do not establish exhaustive special-address coverage; runtime resolver/TLS behavior remains unverified here. Some “never connects” tests only observe a separate ephemeral listener, not all socket attempts (`application/packages/server/src/smtp-connector.test.ts:869`). The environment/loopback integration case also uses a disallowed ephemeral port, confounding that assertion (`application/packages/server/src/smtp-connector.test.ts:915`). Deployed routing, translation, configuration, and the separate email-API transport were not assessed.
