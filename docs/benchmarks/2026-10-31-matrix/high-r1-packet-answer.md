The source implements fail-closed DNS vetting and pins SMTP connections to a vetted IP. This supports specific defenses, **not complete SSRF safety**. No tests or traffic were executed.

- **Ports:** Only integer ports **25, 465, 587, 2525** pass normally. `allowAnyPort: true` bypasses this check entirely. The SMTP send path checks before resolution/connection; tests cover the allowlist, bypass, and stored-port rechecking. `application/packages/server/src/infrastructure/providers/smtp-outbound-policy.ts#L3`, `application/packages/server/src/infrastructure/providers/smtp-client.ts#L198`, `application/packages/server/src/smtp-outbound-policy.test.ts#L11`, `application/packages/server/src/smtp-connector.test.ts#L901`.

- **Address classification:** IPv4 always-denied ranges are `0.0.0.0/8`, `169.254.0.0/16`, `192.0.0.0/24`, multicast `224/4`, reserved `240/4`, plus `100.100.100.200` and `168.63.129.16`. Loopback is `127/8`; private includes RFC1918 and `100.64/10`. IPv6 denies `::`, `fe80::/10`, `ff00::/8`, `64:ff9b::/96`, `2002::/16`, `2001::/32`, and `fd00:ec2::254`; `::1` is loopback and `fc00::/7` private. Zone IDs and invalid IPs are denied. Unmatched valid addresses become “public.” `application/packages/server/src/infrastructure/providers/smtp-outbound-policy.ts#L34`. Tests exercise metadata, range boundaries, private, loopback, and public examples. `application/packages/server/src/smtp-outbound-policy.test.ts#L27`.

- **IPv4 embedded in IPv6:** Dotted tails are converted to hextets. IPv4-mapped forms and IPv4-compatible forms, excluding `::`/`::1`, recursively receive IPv4 classification. This prevents mapped private/metadata/loopback addresses escaping their classification. Tests include dotted and hexadecimal mapped forms; compatible forms lack explicit cases in this suite. `application/packages/server/src/infrastructure/providers/smtp-outbound-policy.ts#L61`, `application/packages/server/src/smtp-outbound-policy.test.ts#L27`.

- **DNS:** Literals bypass lookup. Hostnames use one `lookup(..., {all:true, verbatim:true})`. **Every returned address must pass** before the first is selected: mixed public/forbidden answers fail rather than filtering out forbidden entries. Lookup exceptions and empty answers become `SMTP_TARGET_REFUSED`, suppressing resolver details. Injected-resolver tests cover these behaviors. `application/packages/server/src/infrastructure/providers/smtp-outbound-policy.ts#L117`, `application/packages/server/src/smtp-outbound-policy.test.ts#L81`.

- **Relaxations:** `allowLoopback` permits only loopback; `allowPrivate` controls private addresses and overrides the environment. Otherwise, only exact `SMTP_ALLOW_PRIVATE_HOSTS="true"` enables private destinations. Always-denied addresses remain denied. These options are ordinary parameters, **not guarded by `NODE_ENV`**. The inspected HTTP handler supplies no internal options, whose default policy is `{}`. `application/packages/server/src/infrastructure/providers/smtp-outbound-policy.ts#L139`, `application/packages/server/src/smtp-outbound-policy.test.ts#L105`, `application/packages/server/src/modules/connectors/connector-settings.usecases.ts#L389`, `application/apps/api/src/modules/connectors/connector-settings.controller.ts#L227`.

- **Connection and TLS identity:** Plain TCP and implicit TLS receive `target.address`; STARTTLS wraps that same existing socket. Hostnames remain TLS `servername`, with `rejectUnauthorized:true`; IP literals omit SNI and use IP identity. Thus the inspected path avoids resolving the original hostname again during connection while retaining its certificate identity. `application/packages/server/src/infrastructure/providers/smtp-client.ts#L92`, `application/packages/server/src/infrastructure/providers/smtp-client.ts#L218`. Tests assert single resolution, SNI, untrusted/wrong-name certificate rejection, and successful IP-SAN connections. `application/packages/server/src/smtp-connector.test.ts#L673`.

Remaining gaps: “public” is a denylist fallback, not proof of global routability; other special ranges and translation/routing arrangements remain unproven. Reviewed tests lack negative IP-SAN and STARTTLS hostname-mismatch cases. Actual Node/platform behavior, deployed configuration, network routing, and every caller’s control over relaxation options were not established. The separate email-API dispatch also bypasses this SMTP policy. `application/packages/server/src/infrastructure/providers/smtp-client.ts#L183`.
