The inspected SMTP path vets every returned address and connects using the selected numeric address. This supports specific SSRF defenses, **not complete SSRF safety**. This was source inspection only; no tests or network operations were executed.

- **Ports:** Only integer ports **25, 465, 587, 2525** pass normally. The client checks again before resolving or connecting. `allowAnyPort: true` bypasses this check entirely. Tests assert the allowlist, rejected values, and bypass. `application/packages/server/src/infrastructure/providers/smtp-outbound-policy.ts#L3`, `application/packages/server/src/infrastructure/providers/smtp-client.ts#L198`, `application/packages/server/src/smtp-outbound-policy.test.ts#L11`.

- **Address classes:** IPv4 denies `0/8`, `169.254/16`, `192.0.0/24`, multicast `224/4`, reserved `240/4`, and explicit `100.100.100.200`/`168.63.129.16`. Loopback is `127/8`; private includes RFC1918 plus `100.64/10`. IPv6 denies `::`, `fe80::/10`, `ff00::/8`, `64:ff9b::/96`, `2002::/16`, `2001::/32`, and `fd00:ec2::254`; `::1` is loopback and `fc00::/7` private. Invalid addresses and `%` zone identifiers are denied; otherwise-valid unmatched addresses become “public.” `application/packages/server/src/infrastructure/providers/smtp-outbound-policy.ts#L34`. Tests cover representative classes and boundaries. `application/packages/server/src/smtp-outbound-policy.test.ts#L27`.

- **IPv4 inside IPv6:** The parser normalizes dotted tails and compressed hextets. IPv4-mapped addresses and IPv4-compatible forms, excluding native `::`/`::1`, recursively receive IPv4 classification. The transition prefixes listed above are denied wholesale. Tests cover dotted/hex mapped loopback, private, metadata, and public addresses, plus NAT64/6to4 examples; I found no IPv4-compatible-form cases in this suite. `application/packages/server/src/infrastructure/providers/smtp-outbound-policy.ts#L61`, `application/packages/server/src/smtp-outbound-policy.test.ts#L27`.

- **DNS:** Literals skip lookup. Hostnames use one `lookup(..., {all: true, verbatim: true})`. Every returned address must pass the active policy: one forbidden member rejects a mixed reply. Success selects the first address; exceptions and empty answers become `SMTP_TARGET_REFUSED`. Tests explicitly assert these behaviors. This covers returned results, not every possible DNS answer over time. `application/packages/server/src/infrastructure/providers/smtp-outbound-policy.ts#L117`, `application/packages/server/src/smtp-outbound-policy.test.ts#L81`.

- **Relaxations:** `allowLoopback` permits only loopback. Private addresses require explicit `allowPrivate: true` or exactly `SMTP_ALLOW_PRIVATE_HOSTS="true"`; explicit false overrides the environment. Neither relaxation permits “denied” addresses. These injectable options have **no runtime test-environment guard**. The inspected HTTP controller supplies no internal options, and the use case defaults to `{}`. `application/packages/server/src/infrastructure/providers/smtp-outbound-policy.ts#L139`, `application/packages/server/src/smtp-outbound-policy.test.ts#L105`, `application/packages/server/src/modules/connectors/connector-settings.usecases.ts#L408`, `application/apps/api/src/modules/connectors/connector-settings.controller.ts#L227`.

- **Connection and TLS identity:** TCP and implicit TLS receive `target.address`; STARTTLS wraps the existing socket. DNS hostnames remain `servername`, with `rejectUnauthorized: true`; IP literals omit SNI and use IP identity. This avoids a second application hostname lookup, relying on Node’s numeric-address/TLS semantics. Tests assert one resolution and connection, hostname SNI, untrusted/wrong-name certificate rejection, and IP-SAN success. `application/packages/server/src/infrastructure/providers/smtp-client.ts#L92`, `application/packages/server/src/infrastructure/providers/smtp-client.ts#L217`, `application/packages/server/src/smtp-connector.test.ts#L673`.

Remaining gaps: the finite classifier is not an exhaustive global-routability check; other embedded-address layouts and deployment routing/translation remain unverified. The environment/loopback integration test also uses a disallowed ephemeral port, so rejection can occur before address classification; pure tests isolate that behavior. `application/packages/server/src/smtp-connector.test.ts#L915`. Deployed configuration, resolver behavior, and runtime enforcement were not established.
