## Question-bounded source investigation

Preserve all mandatory workflow, safety, validation and review requirements. This strategy changes source retrieval, not the quality floor.

Before retrieving source, map each requested question to the smallest decisive evidence: implementation block, relevant test block, and evidence limitation. When starting paths are given, read those exact modules and their relevant tests directly; do not spend a separate turn rediscovering known paths. Batch independent reads/searches, include path/line numbers, and read each unchanged block once. Prefer complete small modules or complete relevant functions over entire large registrars, schemas and suites. Expand an incomplete excerpt before drawing a conclusion.

Scope a claim to the evidence needed for the actual question. An API contract investigation can establish which principal ID the handler uses and what its tests assert, while explicitly relying on shared middleware rather than re-auditing the entire middleware, entitlement and access stack. If the question itself asks about authorization, tenant isolation, concurrency or network safety, inspect those boundaries and relevant interleavings fully. Never infer a security guarantee from an interface name, a mock or a partial excerpt. Follow a dependency when it can change the answer; skip adjacent features that cannot, stating relevant unverified assumptions rather than pretending to prove them.

After mandatory startup reads, combine allowed independent mode/progress commands with the first decisive source batch instead of making one tool call per bookkeeping action. A required contract declaration remains its own command. Load a routed policy body when a rule/procedure is unresolved, not to restate instructions already read. Keep required progress reporting.

Before the final answer, check the evidence already held against every requested question and uncertainty. Retrieve only missing decisive evidence. Do not add unrelated validation claims or fetch more context merely to lengthen the answer. Stop when requested behavior, material boundary and evidence limitations are covered; never stop to meet a token budget with an unresolved correctness or safety question.

For this disposable run, `source-context.md` is a deterministic exact-source packet built from the question's starting paths, filename companions and named imports. Read it together with mandatory startup documents; original application files remain available for any missing material dependency. Its listed omitted/unresolved imports and depth limit are retrieval limitations, not proof of absence. It contains no model-generated summaries, expected answers or grading criteria. Cite original application path:line positions shown in the packet. Do not re-fetch included unchanged blocks just to verify formatting; inspect missing boundaries when needed.
