Source inspection supports address vetting and connection pinning in the SMTP path. It does **not** establish complete SSRF safety. No tests, network calls, builds, or application providers were executed.

All paths below are relative to `application/`.

- **Ports:** Only integer ports **25, 465, 587, 2525** pass by default. `allowAnyPort: true` bypasses this policy check entirely. The client checks before DNS resolution or connection; connector settings also validate when saving. `application/packages/server/src/infrastructure/providers/smtp-outbound-policy.ts:3`, `application/packages/server/src/infrastructure/providers/smtp-client.ts:198`, `application/packages/server/src/modules/connectors/connector-settings.usecases.ts:284`. Tests specify allowed/disallowed ports and the override; a connector test covers send-time rechecking. `application/packages/server/src/smtp-outbound-policy.test.ts:11`, `application/packages/server/src/smtp-connector.test.ts:901`.

- **Address classes:** IPv4 hard denials include `0/8`, link-local, `192.0.0/24`, multicast, reserved `240/4`, and two explicit cloud-service addresses. Loopback is `127/8`; “private” includes RFC1918 and `100.64/10`. IPv6 hard denials include unspecified, link-local, multicast, `64:ff9b::/96`, 6to4, Teredo, and AWS metadata; `::1` is loopback and `fc00::/7` private. Invalid addresses and zone identifiers are denied. Unmatched valid IPs become **“public”**, which is a denylist result—not proof of global reachability. `application/packages/server/src/infrastructure/providers/smtp-outbound-policy.ts:34`, `application/packages/server/src/infrastructure/providers/smtp-outbound-policy.ts:84`. Tests cover representative classes and boundaries. `application/packages/server/src/smtp-outbound-policy.test.ts:27`.

- **IPv4 inside IPv6:** Dotted tails and compressed/expanded hextets are parsed. IPv4-mapped and IPv4-compatible forms recursively receive IPv4 classification; native `::` and `::1` retain their special handling. Thus mapped private, loopback, and metadata addresses inherit those restrictions. `application/packages/server/src/infrastructure/providers/smtp-outbound-policy.ts:61`. Tests cover mapped dotted/hexadecimal forms, but I found no explicit IPv4-compatible-form tests. `application/packages/server/src/smtp-outbound-policy.test.ts:28`.

- **DNS:** Literals bypass lookup. Names use `lookup(..., {all:true, verbatim:true})`; **every returned address** must satisfy the active policy before the first is selected. Mixed public/forbidden replies reject the entire target. Exceptions and empty answers become `SMTP_TARGET_REFUSED`, without exposing resolver exception details. `application/packages/server/src/infrastructure/providers/smtp-outbound-policy.ts:117`. Tests specify single resolution, literal bypass, mixed replies, failure, and empty answers. `application/packages/server/src/smtp-outbound-policy.test.ts:81`.

- **Relaxations:** Exactly `SMTP_ALLOW_PRIVATE_HOSTS="true"` permits private addresses; explicit `allowPrivate` overrides it. Loopback requires separate `allowLoopback: true`; hard denials remain enforced. These programmatic seams have **no test-environment guard**. The inspected HTTP endpoint supplies no internal options, and the use case defaults to `{}`. `application/packages/server/src/infrastructure/providers/smtp-outbound-policy.ts:139`, `application/apps/api/src/modules/connectors/connector-settings.controller.ts:227`, `application/packages/server/src/modules/connectors/connector-settings.usecases.ts:408`. `application/packages/server/src/smtp-outbound-policy.test.ts:105`.

- **Actual connection and identity:** Plain TCP and implicit TLS receive the vetted numeric address. STARTTLS wraps that same socket. TLS preserves the original DNS hostname through `servername`, requires certificate authorization, and omits SNI for IP literals; STARTTLS supplies the literal as `host` for identity checking. This relies on Node’s default certificate identity verification. `application/packages/server/src/infrastructure/providers/smtp-client.ts:92`, `application/packages/server/src/infrastructure/providers/smtp-client.ts:218`. Tests specify hostname SNI, untrusted/mismatched certificate rejection, IP SAN success, and one-resolution pinning. `application/packages/server/src/smtp-connector.test.ts:673`.
