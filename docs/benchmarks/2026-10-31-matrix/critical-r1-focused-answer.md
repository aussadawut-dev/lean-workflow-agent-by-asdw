Source inspection supports tenant isolation and permission checks, but does **not establish complete concurrency safety or anonymization**. No tests were executed; these findings do not establish deployed safety.

- **Caller identity and authorization.** JWT verification binds the principal to the registered workspace; scoped middleware rejects resolver/workspace disagreement and establishes workspace context. Controllers pass `scopedPrincipal.userId`, not a body-supplied actor. Each use case resolves that user’s active-workspace membership and current permissions inside its transaction, requiring `connectors.manage`. This is workspace-wide administration, without project membership filtering. See `application/packages/auth/src/principal.ts#L171`, `application/packages/mcp-runtime/src/auth.ts#L78`, `application/apps/api/src/modules/external-identities/external-identity.controller.ts#L12`, `application/packages/server/src/modules/external-identities/external-identity-admin.usecases.ts#L18`, and `application/packages/server/src/modules/access/access.repository.ts#L8`. HTTP tests assert unauthenticated/unauthorized rejection and foreign-workspace 404s, but inject authentication/resolver mocks (`application/apps/api/src/routes/external-identities.test.ts#L22`).

- **Tenant boundaries and listing.** Repository listing, state checks, account lookups and moves carry workspace predicates; the composite account-to-identity foreign key also prevents cross-workspace association. The ID-only final read relies on preceding scoped validation or creation; this path supplies no demonstrated tenant bypass. Listing excludes retired/empty identities, returns at most 1,000, and signals truncation; no explicit snapshot-isolation setting is supplied (`application/packages/server/src/modules/external-identities/prisma-external-identity-admin.repository.ts#L10`, `application/prisma/schema.prisma#L1831`, `application/packages/server/src/modules/external-identities/external-identity-admin.usecases.ts#L26`). Direct tests assert foreign IDs/users and policy overrides are rejected (`application/packages/server/src/external-identities.test.ts#L211`).

- **Concurrency protections and limits.** Merge transactionally locks both identities in sorted order, then rechecks existence/retirement before moving accounts and retiring the source. Split locks its initially found identity, rereads the account, checks account count, then creates/moves. However, if a concurrent merge changes the reread identity, split neither locks that new identity nor restarts; its update also lacks an expected-old-identity predicate. Thus the reread alone does not establish serialization against another operation on the new identity (`application/packages/server/src/modules/external-identities/external-identity-admin.usecases.ts#L40`, `application/packages/server/src/modules/external-identities/prisma-external-identity-admin.repository.ts#L18`). Authorization precedes lock waits without a precommit recheck. HTTP’s conditional post-handler permission recheck can reject a response after the mutation transaction has committed (`application/apps/api/src/app.ts#L299`). These are bounded uncertainties, not a demonstrated exploit. The concurrent test exercises code resolution, not merge/split races (`application/packages/server/src/external-identities.test.ts#L81`).

- **Retirement.** Merge preserves the retired row; allocation counts retired codes and both legacy/current prefixes, with duplicate-skipping insertion and bounded retries. This establishes reservation through these code paths, not database-enforced immutability (`application/packages/server/src/modules/external-identities/external-identity-codes.repository.ts#L19`). Tests assert retirement, rejection of retired participants, and suffix nonreuse (`application/packages/server/src/external-identities.test.ts#L161`, `application/packages/server/src/external-identities.test.ts#L50`).

- **Privacy.** Admin responses intentionally reveal names and account IDs. Ordinary comment/owner reads resolve current pseudonyms, so merges correlate previously separate accounts and splits change subsequent labels (`application/packages/server/src/modules/external-content/external-content.adapter.ts#L184`, `application/packages/server/src/shared/external-owner-identities.ts#L16`). Raw account IDs and comment bodies remain; this is pseudonymization. Tests assert merge-aware reads and selected name-free outputs, but the broad privacy case calls `listExternalIdentities()` without its required caller ID (`application/packages/server/src/external-identity-privacy.test.ts#L88`, `application/packages/server/src/external-identity-privacy.test.ts#L130`). Migration coverage explicitly retains malformed object-shaped owner data, including its name (`application/packages/server/src/external-identity-privacy.test.ts#L220`).

Bounded missing regressions: coordinate reverse/overlapping merges; force split’s identity to change between lookup and lock, then race another split/merge; revoke permission during a lock wait and inspect committed state; verify split-aware comment/owner reads. Repair the privacy fixture’s caller ID and distinguish structured-name protection from free-text privacy. No implementation changes are proposed here.
