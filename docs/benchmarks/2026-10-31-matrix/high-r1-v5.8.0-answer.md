The inspected SMTP path **vets addresses before connecting and passes the selected IP to TCP/TLS**, while retaining the configured hostname for TLS identity. This is source evidence, not proof of complete SSRF safety. No tests or network operations were executed.

- **Ports:** Only integer ports **25, 465, 587, 2525** pass by default. The client rechecks at send time, before resolution. `allowAnyPort: true` bypasses the entire policy check. Tests enumerate allowed/disallowed ports and exercise that override. `application/packages/server/src/infrastructure/providers/smtp-outbound-policy.ts:3`, `application/packages/server/src/infrastructure/providers/smtp-client.ts:198`, `application/packages/server/src/smtp-outbound-policy.test.ts:11`.

- **Address classification:** IPv4 denies `0/8`, `169.254/16`, `192.0.0/24`, multicast `224/4`, reserved `240/4`, and exact addresses `100.100.100.200` and `168.63.129.16`. Loopback is `127/8`; private includes RFC1918 and `100.64/10`. IPv6 denies `::`, `fe80::/10`, `ff00::/8`, `64:ff9b::/96`, `2002::/16`, `2001::/32`, and `fd00:ec2::254`; `::1` is loopback and `fc00::/7` private. Invalid addresses and anything containing `%` are denied.
