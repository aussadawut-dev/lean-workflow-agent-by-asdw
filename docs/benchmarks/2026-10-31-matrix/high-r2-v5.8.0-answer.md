The SMTP path implements address filtering and connection pinning, but this source inspection does **not establish complete SSRF safety**. No tests were executed or traffic sent. Paths below are under `application/`.

- **Ports:** Only integer ports **25, 465, 587, 2525** pass normally. `allowAnyPort: true` bypasses the entire policy check. Sending rechecks the port before DNS/socket creation. See `application/packages/server/src/infrastructure/providers/smtp-outbound-policy.ts:3`, `application/packages/server/src/infrastructure/providers/smtp-client.ts:198`. Tests cover allowed ports, invalid values, and bypass behavior: `application/packages/server/src/smtp-outbound-policy.test.ts:11`.

- **Address classes:** IPv4 denies `0/8`, `169.254/16`, `192.0.0/24`, `224/4`, `240/4`, and exact addresses `100.100.100.200`, `168.63.129.16`; `127/8` is loopback; RFC1918 ranges and `100.64/10` are private. IPv6 denies `::`, `fe80::/10`, `ff00::/8`, `64:ff9b::/96`, `2002::/16`, `2001::/32`, and `fd00:ec2::254`; `::1` is loopback, `fc00::/7` private. Invalid addresses and zone identifiers containing `%` are denied. Remaining valid addresses default to “public,” which is **not proof of global routability**. Implementation: `application/packages/server/src/infrastructure/providers/smtp-outbound-policy.ts:34`; representative tests: `application/packages/server/src/smtp-outbound-policy.test.ts:27`.

- **IPv4 embedded in IPv6:** The parser handles dotted tails and compressed/expanded hexadecimal forms. IPv4-mapped `::ffff:a.b.c.d` and IPv4-compatible forms under `::/96`, excluding `::` and `::1`, are recursively classified as IPv4. Thus mapped metadata, private, and loopback addresses inherit their restrictions. See `application/packages/server/src/infrastructure/providers/smtp-outbound-policy.ts:61`. Tests include dotted/hex mapped addresses, but I found no explicit IPv4-compatible or `2001::/32` cases in the inspected classification suite.

- **DNS:** Literals skip resolution. Hostnames use `lookup({all:true, verbatim:true})`; **every returned address must pass**, including later entries in mixed replies. Only then is the first returned. Resolver exceptions and empty answers both produce `SMTP_TARGET_REFUSED`. See `application/packages/server/src/infrastructure/providers/smtp-outbound-policy.ts:117`; tests cover single resolution, literal bypass, mixed refusals, failure, and emptiness: `application/packages/server/src/smtp-outbound-policy.test.ts:81`.

- **Relaxations:** `SMTP_ALLOW_PRIVATE_HOSTS` must equal lowercase `"true"`; explicit `allowPrivate` overrides it. Neither permits loopback or always-denied classes. `allowLoopback` permits only loopback. These programmatic seams have **no `NODE_ENV` restriction**; calling them “test-only” describes intended use, not enforced isolation. Tests verify environment spelling and override precedence: `application/packages/server/src/smtp-outbound-policy.test.ts:105`. The inspected HTTP controller passes only role and recipient, exposing no policy argument: `application/apps/api/src/modules/connectors/connector-settings.controller.ts:227`.

- **Connection and TLS identity:** Plain TCP and implicit TLS receive the vetted numeric address; STARTTLS wraps that existing socket. Hostnames supply the original `servername`, with `rejectUnauthorized:true`; literals omit SNI and preserve IP verification identity. See `application/packages/server/src/infrastructure/providers/smtp-client.ts:92`, `application/packages/server/src/infrastructure/providers/smtp-client.ts:217`. Tests assert pinning, SNI, untrusted/wrong-name rejection, and IP-SAN success: `application/packages/server/src/smtp-connector.test.ts:673`.

Remaining gaps include unexecuted runtime behavior, incomplete address/boundary coverage, and deployment routing/environment configuration. Some refusal tests’ zero-connection counters observe only an ephemeral loopback listener while the configured destination is elsewhere, so they do not independently prove absence of socket attempts: `application/packages/server/src/smtp-connector.test.ts:268`, `application/packages/server/src/smtp-connector.test.ts:858`. The separate email-API branch precedes SMTP checks and was outside this audit.
