Source supports workspace-scoped authorization and transactional mutations, but does **not establish complete concurrency or privacy safety**. No exploitable authorization bypass was demonstrated. This was source inspection only; no tests ran, and deployed configuration remains unknown.

- **Caller identity and authorization.** The verifier derives workspace identity from a registered issuer after JWT verification (`application/packages/auth/src/principal.ts#L171`). Middleware rejects resolver/workspace disagreement and binds workspace context (`application/packages/mcp-runtime/src/auth.ts#L78`); controllers pass `scopedPrincipal.userId`, not a body-supplied actor (`application/apps/api/src/modules/external-identities/external-identity.controller.ts#L11`). All three routes require `connectors.manage` (`application/packages/contracts/src/access-routes.ts#L44`). Each use case resolves authorization again inside its transaction; resolution checks the user’s workspace, active workspace, database role, policy and entitlements (`application/packages/server/src/modules/external-identities/external-identity-admin.usecases.ts#L18`, `application/packages/server/src/modules/access/access.repository.ts#L8`). Access is workspace-wide; no project-membership check restricts the identity list.

- **Tenant boundaries and retirement.** List/state/account queries and locks include workspace predicates. Final identity reads and retirement updates use ID alone, relying on earlier scoped checks or scoped creation (`application/packages/server/src/modules/external-identities/prisma-external-identity-admin.repository.ts#L12`). The schema additionally requires account and identity workspace IDs to agree through a composite relation (`application/prisma/schema.prisma#L1856`). Merge retains the source row as retired; allocation considers both code prefixes and retired rows, with duplicate-skipping insertion and bounded retries (`application/packages/server/src/modules/external-identities/external-identity-codes.repository.ts#L19`, `application/packages/server/src/modules/external-identities/external-identity-codes.repository.ts#L62`). Reservation is workspace-local and depends on retaining those records.

- **Concurrency limits.** Merge locks deduplicated IDs in sorted order, rereads both states, rejects retired identities, then moves accounts and retires atomically (`application/packages/server/src/modules/external-identities/prisma-external-identity-admin.repository.ts#L10`, `application/packages/server/src/modules/external-identities/external-identity-admin.usecases.ts#L40`). Split rereads account membership after locking, but if membership changed while waiting, it neither locks the newly observed identity nor retries (`application/packages/server/src/modules/external-identities/external-identity-admin.usecases.ts#L55`). That is a bounded investigation target, not proof of corruption. No isolation level is specified here. Authorization is checked before identity-lock waits, without a final transaction-local permission recheck. HTTP’s post-handler recheck can reject a response after mutation commit; it cannot undo that commit (`application/apps/api/src/app.ts#L299`).

- **Privacy impact.** Authorized lists deliberately disclose names, account IDs, timestamps and cross-system associations (`application/packages/server/src/modules/external-identities/external-identity-admin.usecases.ts#L11`). Pseudonymous owner output retains provider account IDs and resolves current mappings, so merge increases linkability across systems; split changes mapping rather than erasing history (`application/packages/server/src/shared/external-owner-identities.ts#L11`). Outbound text is stored, and tests expect later posts to use the merged code (`application/packages/server/src/modules/comment-outbound/comment-outbound.adapter.ts#L74`, `application/packages/server/src/comment-outbound.test.ts#L349`). This is pseudonymization, not anonymity or retrospective deletion.

- **Evidence and bounded regressions.** Tests assert tenant/permission denial and sequential retirement/split behavior (`application/apps/api/src/routes/external-identities.test.ts#L43`, `application/packages/server/src/external-identities.test.ts#L161`). Concurrent tests exercise allocation, not merge/split (`application/packages/server/src/external-identities.test.ts#L81`). Privacy assertions cover selected names and outputs, but one calls the now actor-required list function without an argument (`application/packages/server/src/external-identity-privacy.test.ts#L88`). Propose barrier-controlled tests for opposing merges, merge-versus-split with changed membership, duplicate splits, and permission revocation during a lock wait; assert rollback, account conservation and no accounts on retired identities. Add post-split comment/owner/outbound assertions and repair the stale privacy-test caller before relying on that suite.
