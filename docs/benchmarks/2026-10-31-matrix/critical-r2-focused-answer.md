The inspected paths provide layered tenant and authorization checks. They do **not** establish complete concurrency safety or anonymity. No tests were executed; these are source findings, not deployed-safety guarantees.

- **HTTP caller and authorization.** JWT verification uses a registered issuer, verifies signature/audience, and derives workspace identity from that registry (`application/packages/auth/src/principal.ts:171`). The local resolver requires verified email, scopes subject/email matching by workspace, and rejects conflicting bindings (`application/packages/db/src/project-scope.ts:67`). Middleware rejects resolver/workspace disagreement and establishes workspace context (`application/packages/mcp-runtime/src/auth.ts:78`); controllers pass `scopedPrincipal.userId`, not a body-supplied actor (`application/apps/api/src/modules/external-identities/external-identity.controller.ts:11`). HTTP permission checks precede handlers; use cases independently reload membership, active-workspace state, policy and entitlement inside their transaction, then require `connectors.manage` (`application/apps/api/src/app.ts:282`, `application/packages/server/src/modules/access/access.repository.ts:8`, `application/packages/server/src/modules/external-identities/external-identity-admin.usecases.ts:18`). Access is workspace-wide, without a project filter.

- **Tenant boundaries.** List filters workspace, active status and nonempty accounts, returning at most 1,000 identities. Merge locks and finds both IDs within the workspace; split resolves accounts by `(workspaceId, kind, accountId)` (`application/packages/server/src/modules/external-identities/prisma-external-identity-admin.repository.ts:12`). The composite foreign key prevents cross-workspace account attachment (`application/prisma/schema.prisma:1856`). Final identity reads and source retirement use ID alone, but these callers supply previously scoped or newly created IDs; I found no supported cross-tenant path. Server tests cover foreign IDs, outsiders and policy denial (`application/packages/server/src/external-identities.test.ts:211`); HTTP tests cover 401/403/404, but inject authentication/resolution doubles (`application/apps/api/src/routes/external-identities.test.ts:22`).

- **Transactions and concurrency.** Merge sorts/deduplicates IDs, obtains `FOR UPDATE` locks, then rechecks existence/retirement before moving accounts and retiring the source atomically (`application/packages/server/src/modules/external-identities/prisma-external-identity-admin.repository.ts:10`, `application/packages/server/src/modules/external-identities/external-identity-admin.usecases.ts:40`). Split re-reads membership after locking the initially found identity, then counts accounts and moves one to a fresh identity. If membership changed while waiting, it does **not** lock the newly found identity or explicitly recheck retirement (`application/packages/server/src/modules/external-identities/external-identity-admin.usecases.ts:55`). No isolation override or transaction retry appears here. Authorization rows are not locked; the HTTP post-handler permission recheck cannot roll back an already committed mutation (`application/apps/api/src/app.ts:304`). These limit concurrency guarantees; they do not demonstrate an exploit.

- **Retirement.** Merge retains the retired row; allocation considers active and retired numbers under both prefixes, with duplicate-skipping insertion and bounded retries (`application/packages/server/src/modules/external-identities/external-identity-codes.repository.ts:19`). Sequential retirement, rejection and non-reuse are asserted (`application/packages/server/src/external-identities.test.ts:161`). Concurrent tests exercise resolution/allocation, **not** merge/split (`application/packages/server/src/external-identities.test.ts:81`); preservation depends on retaining those rows.

- **Privacy.** Admin responses intentionally expose account IDs, real names, timestamps and account linkage (`application/packages/server/src/modules/external-identities/external-identity-admin.usecases.ts:11`). Ordinary owner/comment reads resolve current pseudonyms while retaining provider IDs; merging increases linkability (`application/packages/server/src/shared/external-owner-identities.ts:16`, `application/packages/server/src/modules/external-content/external-content.adapter.ts:183`). Privacy tests assert selected AI/notification/storage paths exclude fixture names and later reads follow merges (`application/packages/server/src/external-identity-privacy.test.ts:88`, `application/packages/server/src/external-identity-privacy.test.ts:130`). However, line 112 omits the required list caller ID. These fixtures establish neither arbitrary-content redaction nor historical-output erasure; split cannot erase previously observed linkage.
