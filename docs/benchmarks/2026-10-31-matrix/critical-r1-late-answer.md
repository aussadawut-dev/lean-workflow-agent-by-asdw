Source supports tenant isolation and sequential authorization checks, but does **not establish complete concurrency safety**. Tests were inspected, not executed; no deployed-safety or exploit claim follows.

- **Caller and authorization.** Shared middleware verifies the bearer token, rejects resolver/workspace mismatches, and installs workspace context (`application/packages/mcp-runtime/src/auth.ts:59`). Controllers pass `scopedPrincipal.userId`, never a body-selected actor (`application/apps/api/src/modules/external-identities/external-identity.controller.ts:11`). All three use cases resolve the caller inside their transaction and require workspace-level `connectors.manage`; resolution checks local membership, active workspace, policy and entitlements (`application/packages/server/src/modules/external-identities/external-identity-admin.usecases.ts:18`, `application/packages/server/src/modules/access/access.repository.ts:8`). HTTP middleware additionally checks workspace writability for mutations (`application/apps/api/src/app.ts:270`). These are workspace-wide operations, without project-level filtering.

- **Tenant boundaries.** Listing selects active, nonempty identities from the current workspace, capped at 1,000 with truncation reporting. Merge scopes locks and state reads; split scopes account lookup, counting and movement (`application/packages/server/src/modules/external-identities/prisma-external-identity-admin.repository.ts:12`). Final reads and source retirement use ID alone, relying on preceding scoped validation. The composite account-to-identity foreign key enforces matching workspaces (`application/prisma/schema.prisma:1848`). Tests assert foreign-ID rejection, caller isolation, permission overrides and foreign-workspace reassignment failure (`application/packages/server/src/external-identities.test.ts:129`, `application/packages/server/src/external-identities.test.ts:211`). HTTP tests cover 401/403/404 and strict bodies, but inject authentication/resolution (`application/apps/api/src/routes/external-identities.test.ts:22`).

- **Merge and retirement.** One transaction locks both identities in sorted order, rereads existence/retirement, moves accounts, and retires the source (`application/packages/server/src/modules/external-identities/external-identity-admin.usecases.ts:35`, `application/packages/server/src/modules/external-identities/prisma-external-identity-admin.repository.ts:18`). This supports serialization between cooperating overlapping merges. Allocation includes retired codes and both legacy/current prefixes, with uniqueness and bounded insertion retries (`application/packages/server/src/modules/external-identities/external-identity-codes.repository.ts:19`, `application/packages/server/src/modules/external-identities/external-identity-codes.repository.ts:62`). Sequential tests assert retirement, rejection of retired participants, and nonreuse (`application/packages/server/src/external-identities.test.ts:161`); they do not establish simultaneous merge behavior.

- **Concurrency gaps.** Split finds identity A, locks A, then rereads the account’s *current* identity without requiring equality or locking a changed identity (`application/packages/server/src/modules/external-identities/external-identity-admin.usecases.ts:52`). A supported investigation path is: merge A→B commits while split waits; split then counts B while holding A’s lock. Whether competing operations violate intended invariants needs controlled interleaving tests. Transactions specify no isolation override (`application/packages/server/src/modules/external-identities/prisma-external-identity-admin.repository.ts:10`). Authorization is checked before lock waits; HTTP’s later permission recheck occurs after use-case completion and cannot undo committed mutations (`application/apps/api/src/app.ts:304`). Existing concurrent tests exercise allocation, not admin operations (`application/packages/server/src/external-identities.test.ts:81`).

- **Privacy impact.** Admin responses deliberately disclose names, account IDs and timestamps. Merge links accounts across systems; split changes one account’s current pseudonym, without erasing names or historical disclosures. Readers resolve current codes, so later comment/owner reads follow changed mappings while retaining external account IDs (`application/packages/server/src/modules/external-content/external-content.adapter.ts:184`, `application/packages/server/src/shared/external-owner-identities.ts:16`). Privacy tests assert pseudonyms across selected reads, AI calls, notifications and storage—not arbitrary content, logs or all surfaces (`application/packages/server/src/external-identity-privacy.test.ts:76`). One case calls the now-required-user-ID list function without an argument, limiting confidence in that case (`application/packages/server/src/external-identity-privacy.test.ts:112`).

Bounded regressions: barrier-controlled opposing/overlapping merges; split-after-merge with another split on B; revocation/deactivation during lock waits; rollback after movement/allocation; and post-split comment/owner privacy reads. Assert account conservation, active destinations, retirement nonreuse, and defined authorization timing.
