Source inspection supports workspace isolation and layered authorization, but does **not establish complete concurrency safety**. I found no demonstrated cross-tenant exploit. No tests, builds, database calls or network access were executed.

- **HTTP caller and permissions.** Scoped authentication verifies the bearer token, resolves a local principal, rejects workspace disagreement and binds workspace/access context (`application/packages/mcp-runtime/src/auth.ts#L69`). The default resolver requires verified email and matching workspace-scoped subject/email records (`application/packages/db/src/project-scope.ts#L46`). Controllers pass `scopedPrincipal.userId`, not a body-supplied caller (`application/apps/api/src/modules/external-identities/external-identity.controller.ts#L12`). All three routes require `connectors.manage` (`application/packages/contracts/src/access-routes.ts#L44`); each use case additionally reloads the subject inside its transaction. That lookup requires membership in the current active workspace and derives policy/entitlement permissions (`application/packages/server/src/modules/access/access.repository.ts#L8`).

- **Tenant boundaries.** Listing filters by workspace, active status and account presence; merge locks and rechecks both IDs within the workspace; split locates the account by workspace/kind/accountId (`application/packages/server/src/modules/external-identities/external-identity-admin.usecases.ts#L26`, `application/packages/server/src/modules/external-identities/prisma-external-identity-admin.repository.ts#L12`). Although final reads and retirement updates use ID alone, those IDs come from scoped validation/allocation. The composite foreign key prevents attaching an account to another workspace’s identity (`application/prisma/schema.prisma#L1831`). I found no supported bypass through these paths.

- **Transactions and concurrency.** Merge uses one transaction, sorted/deduplicated `FOR UPDATE` locks, then checks existence/retirement before moving accounts and retiring the source (`application/packages/server/src/modules/external-identities/prisma-external-identity-admin.repository.ts#L10`). This supports serialization among overlapping merges. Split rechecks after locking, but **does not lock a changed identity**: an intervening merge can move the account A→B before split locks A; split then counts B and moves the account while holding A’s lock (`application/packages/server/src/modules/external-identities/external-identity-admin.usecases.ts#L57`). Thus its locking argument is incomplete for subsequent operations on B. No explicit isolation level, retry loop or account compare-and-set appears here; actual anomalies remain unverified. Authorization is checked before identity-lock waits. HTTP middleware conditionally rechecks permissions after the handler, but that cannot undo an already committed mutation (`application/apps/api/src/app.ts#L299`).

- **Retirement and privacy.** Merge preserves the target code and retains the retired source row. Allocation includes retired and legacy-prefix suffixes and retries conflicting inserts (`application/packages/server/src/modules/external-identities/external-identity-codes.repository.ts#L19`). This reserves codes within the workspace while records remain retained. Admin responses deliberately expose names, account IDs and timestamps. Ordinary comment reads substitute current codes but retain external account IDs and bodies (`application/packages/server/src/modules/external-content/external-content.adapter.ts#L183`). Merge therefore increases cross-system linkability; split changes future lookup mappings, without erasing previously observed associations. Pseudonymization is not anonymity or content redaction.

Tests encode HTTP denial, foreign-workspace exclusion and sequential merge/split behavior (`application/apps/api/src/routes/external-identities.test.ts#L36`); server tests cover retirement reservation, split semantics, composite-FK isolation and policy denial (`application/packages/server/src/external-identities.test.ts#L129`). Concurrent tests exercise **resolution/allocation**, not admin merge/split (`application/packages/server/src/external-identities.test.ts#L81`). Privacy tests check selected name-bearing fields and merge-following reads, but one calls `listExternalIdentities()` without its required user ID, limiting confidence in that suite’s current validity (`application/packages/server/src/external-identity-privacy.test.ts#L112`).

Bounded missing regressions: barrier-controlled opposing merges; split after A→B movement followed by another split/merge on B; policy revocation during lock wait with committed-state assertions; and post-split comment/owner reads plus denied-response privacy checks. These would test unresolved guarantees, not confirm an exploitable bug.
