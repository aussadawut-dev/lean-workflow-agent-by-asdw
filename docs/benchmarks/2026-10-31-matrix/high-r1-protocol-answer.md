The source implements layered SMTP SSRF defenses and pins connections to a vetted IP while retaining TLS hostname identity. This is source evidence, not proof of complete SSRF safety. No traffic was sent and no tests were executed.

- **Ports:** Only integer ports **25, 465, 587, and 2525** pass by default. `allowAnyPort: true` bypasses this policy check entirely. The sender checks the port before resolution or connection. Assertions cover invalid ports, the bypass, and send-time rejection. `application/packages/server/src/infrastructure/providers/smtp-outbound-policy.ts:3`, `application/packages/server/src/infrastructure/providers/smtp-client.ts:198`, `application/packages/server/src/smtp-outbound-policy.test.ts:11`, `application/packages/server/src/smtp-connector.test.ts:901`.

- **Address classification:** IPv4 denial covers `0/8`, `169.254/16`, `192.0.0/24`, multicast `224/4`, `240/4`, and explicit addresses `100.100.100.200` and `168.63.129.16`. Loopback is `127/8`; private includes RFC1918 ranges and `100.64/10`. IPv6 denial covers `::`, `fe80::/10`, `ff00::/8`, `64:ff9b::/96`, `2002::/16`, `2001::/32`, and `fd00:ec2::254`; `::1` is loopback and `fc00::/7` private. Zone identifiers and invalid IPs are denied. Other valid addresses fall through to “public.” `application/packages/server/src/infrastructure/providers/smtp-outbound-policy.ts:34`.

- **Embedded IPv4:** Dotted and hexadecimal IPv6 forms are expanded. IPv4-mapped addresses and IPv4-compatible forms, excluding `::`/`::1`, recursively receive IPv4 classification. Thus mapped metadata/private/loopback addresses retain those restrictions. Tests cover mapped dotted/hex forms and selected translation prefixes, but lack explicit compatible-form assertions. `application/packages/server/src/infrastructure/providers/smtp-outbound-policy.ts:61`, `application/packages/server/src/smtp-outbound-policy.test.ts:27`.

- **DNS:** Literals skip lookup; hostnames use `lookup({all:true, verbatim:true})`. Every returned address must be permitted before the first is selected: one disallowed answer rejects a mixed response. Lookup exceptions and empty results become `SMTP_TARGET_REFUSED`. Tests assert single resolution, literal bypass, mixed-answer refusal, failure, and empty answers. `application/packages/server/src/infrastructure/providers/smtp-outbound-policy.ts:117`, `application/packages/server/src/smtp-outbound-policy.test.ts:81`.

- **Relaxations:** `allowLoopback` permits only loopback; `allowPrivate` overrides the environment, otherwise only exact `SMTP_ALLOW_PRIVATE_HOSTS="true"` permits private addresses. Neither overrides “denied.” These programmatic seams have no `NODE_ENV` guard. The inspected HTTP controller passes no internal options. Tests assert environment spelling and override behavior. `application/packages/server/src/infrastructure/providers/smtp-outbound-policy.ts:139`, `application/apps/api/src/modules/connectors/connector-settings.controller.ts:227`, `application/packages/server/src/smtp-outbound-policy.test.ts:105`.

- **Connection and TLS:** Plain TCP and implicit TLS receive `target.address`; STARTTLS wraps that existing socket. Hostnames remain `servername`, with `rejectUnauthorized:true`. IP literals omit SNI; STARTTLS supplies the literal as `host` for identity checking. Assertions cover hostname SNI, untrusted/wrong-name certificates, IP-SAN success, and one-resolution TCP delivery. `application/packages/server/src/infrastructure/providers/smtp-client.ts:92`, `application/packages/server/src/infrastructure/providers/smtp-client.ts:218`, `application/packages/server/src/smtp-connector.test.ts:673`.

Remaining gaps include exhaustive special-address/translation-prefix coverage, IPv6 socket behavior, TLS-specific lookup-count assertions, and IP-SAN mismatch rejection. The single-resolution test uses plaintext. Some refusal tests count connections to an unrelated ephemeral listener; the no-seam loopback test also uses a forbidden port, so it does not independently isolate address rejection. `application/packages/server/src/smtp-connector.test.ts:744`, `application/packages/server/src/smtp-connector.test.ts:858`. Runtime TLS behavior, deployed configuration, routing/NAT, and egress controls remain unverified.
