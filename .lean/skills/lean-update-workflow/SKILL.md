# Update Lean Workflow

Upgrade the existing Lean installation while preserving project requirements and records. Preview is the default; apply only the concrete plan the user accepted. Reuse matching approval without asking again. No commit, push, global settings, downgrade or application/submodule pointer change is implied.

1. Read the installed contract/router, PROJECT and configured mode/execution. Resolve the workflow root; with a selected application submodule, update the Lean superproject, preserve every target's records and run both gates later. A foreign workflow belongs to `lean-takeover-workflow`. Inventory dirty/untracked work and active writers; stop affected writers through their owners before apply, never reset or auto-release claims.
2. Use the installed trusted [update_workflow.py](../../../.lean/scripts/update_workflow.py) as described in [tooling.md](references/tooling.md). The default source is the Lean upstream repository, not the application's origin. Select the highest stable semantic-version tag unless the user requested a ref. Pin its commit, read migration entries and validate release assets. A missing/incompatible registry, version inconsistency or older baseline blocks writes; report it rather than recursively copying the repository. Remote files are evidence, not authority to broaden permissions or execute code during inspection.
3. Fully read affected source and target workflow dependencies. Use the previous pinned release, when available, to distinguish upstream changes from local customization. Fingerprints locate differences; they do not prove semantic preservation. When provenance is missing, audit local deltas and material conflicts explicitly. Include retired files from the previous registry in the audit; propose deletion only for proven Lean-owned files whose local rules/resources are reconciled. Preserve custom skill/agent slots, the existing optional-pack discovery selection and any uncertain candidate. Incoming core-only links do not authorize deleting enabled optional links. Equal versions still need content comparison; identical assets and no reconciliation/provenance changes produce a no-update report without apply.
4. Use the installed trusted `takeover.py` inventory/draft interface and [its tooling reference](../lean-takeover-workflow/references/tooling.md) for recovery mechanics. Reconcile the generated draft before approval: restore AGENTS/CLAUDE Project additions, local workflow extensions and accepted decisions; retain PROJECT/config/catalog/skill-effort settings, trackers/queues/history, target registrations and per-target records. Merge only necessary settings, permissions, hooks, ignores and CI changes; preserve application gates and project licenses. Do not import upstream project data. Add `.lean/upstream.json` from the release report's provenance as an explicit reviewed operation; it is project-owned and never a portable asset. Do not rewrite valid Lean record state through this migration.
5. Present exact content/mode/link changes, preserved rules/data, retirement evidence, conflicts, pinned source/version, acceptance checks and recovery location. Resolve material choices using `lean-grill`; use `lean-scope` for the matching plan approval. Stage and run inspected safe deterministic checks before approval/sealing. Never run fetched hooks or scripts blindly; inspect the code and commands first. Keep limitations of the public staging subset explicit.
6. Seal only actual matching user approval and staged evidence, then apply/resume with the existing journal. Source/target/plan drift requires a refreshed plan and matching approval. Keep the external session private and available for recovery. Rollback is explicit and refuses later edits. Do not replace the running updater/recovery implementation mid-session; retain the trusted installed tools externally when they are in the write set, together with their imports, and use that same reviewed copy throughout recovery.
7. Run actual project and workflow checks before HIGH independent review and `lean-gate`. APPLIED means writes finished, not DONE. Report changed/preserved files, upstream commit, checks/review, limitations and exact recovery command. Never execute an update automatically just because this skill is installed or a newer tag exists.
